What is a Data Flow Diagram (DFD)?

A Data Flow Diagram (DFD) is a graphical representation of the "flow" of data through an information system. It models the system's process aspects, showing what kinds of information will be input to and output from the system, where data comes from and where it goes, and where the data is stored.

Unlike control flowcharts or UML activity diagrams, DFDs contain no control logic, loops, or conditional branching (such as if/else). Instead, they strictly describe the transformation and transmission of data between processes, stores, and external actors.

The 5 Cardinal Axioms of DFDs

Rule 1: No Direct Entity-to-Entity Flows
An external entity cannot directly send data to another external entity within your system boundary. If two entities exchange information without involving the system, that interaction is outside the scope of the system.
Rule 2: No Direct DataStore-to-DataStore Flows
A data store cannot move data directly into another data store without a computational process reading from one and writing to the other.
Rule 3: No Direct Entity-to-DataStore Flows
An external user or actor cannot directly write or read from a database table or file without passing through a process that validates and executes the operation.
Rule 4: Every Process Must Have at least One Input and One Output
A process with only output flows is a Miracle Process. A process with only input flows is a Black Hole Process. Both violate conservation of data.
Rule 5: Level Balancing Axiom
The inputs and outputs entering and leaving the single system process in Level 0 Context Diagram must match exactly with the external boundary flows in Level 1 Decomposition.

DFD Level Hierarchy Explained

Represents the entire system as a single process labeled Process 0. Shows the system boundary, external actors (users, banks, sensors, suppliers), and major input/output data flows. Data stores are intentionally excluded because all internal databases are encapsulated within the system.

Explodes Process 0 into major functional sub-processes (1.0, 2.0, 3.0, 4.0...). Introduces internal Data Stores (D1, D2, D3...), shows how data flows between processes, and maps interactions with external entities.

Decomposes a complex Level 1 process (e.g. Process 3.0 "Order Placement") into fine-grained sub-steps (3.1 "Validate Stock", 3.2 "Calculate Tax", 3.3 "Apply Coupon", 3.4 "Charge Credit Card").
